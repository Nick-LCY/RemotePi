- 2026-09-11（在线热修复 — bridge 重连状态机对 undici close 缺发的防御，commit `e391916`）— **根因一句**：bridge 用 Node 22 内置 `globalThis.WebSocket = undici`（非 `ws` 包），undici 在所有建连失败场景（HTTP 非 101 / ECONNREFUSED / SYN 黑洞）只派发 `onerror`、**永不派发 `onclose`**，错误消息统一为 "Received network error or non-101 status code."（网络错误与非 101 HTTP 响应混淆）；叠加僵尸 socket close 事件迟到（Linux `tcp_retries2=15` 重传预算耗尽，实测 11:20:12 → 11:37:35 = **17 分 24 秒**）；bridge 重连只由 `onclose` 驱动、`handleError` 是纯日志（注释假设 "close event is the authoritative signal" 是浏览器规范假设，undici 违反之）→ 进程活着、零定时器、重连状态机永久停摆。**实验实证**（开发机 Node v22.23.1 / undici 7.29.0）：A 503 @29ms error 永 close；B1 ECONNREFUSED @18ms error 永 close；B2 SYN 黑洞 @~5s error 永 close；C1/C2/C3 已建连后 RST/FIN close(1006) 2-3ms 即到；C4/C6 已建连后纯静默 close 事件不来由 ADR-0011 read-idle 兜底。**修复一句**：身份守卫四 handler（`if (ws !== this.ws) return;` 拒绝旧 socket 迟到事件）+ `handleError` 仅在 CONNECTING 阶段驱动 `handleClose`（OPEN error 保持 log-only，避免与必到的 close 竞争）+ `handleIdleTimeout` 立即合成 `handleClose` 调度重连（消除 17 分钟空窗，不加 connect 阶段 watchdog）；**不加 connect 阶段 watchdog**（实测所有失败秒级到达，watchdog 冗余且新增定时器管理负担）。**数字**：bridge 单测 **372 → 378**（+6：5g/5h/5i/5j/5k/5l）/ shared 136 零回归 / 集成 32/32 零回归 / web 单测与 e2e 未跑（工作区有 M5 第二块任务 04 in-flight dirty area 不属本修复；web 3 个在途失败用例经 stash 验证为 M5-04 自身所致） / typecheck ✓ / lint 0 error / bridge+shared build 绿。**review 0 Critical / 0 blocking Warning / 3 Suggestions 全部落地**（CONNECTING 日志文案分支 / 5i 僵尸 warn 面包屑断言 / `readReconnectDelay` 前缀钉桩）。**协议 / worker / web / shared 零改动**；**需服务器重启 bridge 加载**（与「TODO / 阻塞」中"服务器端 bridge 更新重启"为同一动作，重启同时加载 ADR-0011 read-idle + ADR-0012 退避门控 + 本修复）。**修复性质**：在线热修复（类 ADR-0011 / ADR-0012 先例），无对应里程碑任务文件（M5 第一块 2026-09-11 已收官；M5 第二块 2026-09-11 立项 D8-D13，5 任务 todo，本修复不属其中任一）。详见 [[architecture/decisions/0013-bridge-reconnect-undici-close-missing-defense.md|ADR-0013]]。
